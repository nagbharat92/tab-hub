# Limits and review status

The structural-design build is **0.4.0 on `round-2`**, not installed in the user's active Chrome profile, merged into `main` or released. Existing v0.3.0 data is left intact. Review it in a disposable Chromium profile using the instructions in [`process/round-2/START_HERE.md`](process/round-2/START_HERE.md).

- **Missing round-two sources:** The v0.1 addendum, Siri reference images, curated demo `.tabhub` archive and v0.1.2 recordings named in the brief were not supplied. The migration and screenshot/recording matrix use synthetic fixtures and local public-URL tests instead; identical-data before/after comparison is unavailable. The brief also leaves the time/spend ceiling blank; no ceiling can honestly be declared reached. See [`process/round-2/BLOCKERS.md`](process/round-2/BLOCKERS.md).
- **Backups are user controlled.** Local browser data can be lost with the profile, extension removal or disk failure. Export a `.tabhub` archive and store it privately: it contains browsing history and is not encrypted. The current in-memory archive has a 500 MB limit; streaming backups are not implemented. An old downloaded archive may still contain content later deleted from the current profile.
- **Model guesses are conditional.** The no-op and existing local Chrome `LanguageModel` paths are implemented, but the real on-device model has not been exercised in a user browser. A model is never downloaded automatically, no page data goes to hosted inference, and saved pages do not depend on a guess. Guesses are stored and searchable but intentionally not editable/displayed in the 0.4.0 panel.
- **Capture permissions and browser limits.** Broad site access remains from v0.3 to preserve one-action arbitrary-group preview capture; a narrower per-origin permission flow needs a separate reliable design. Chrome can capture only the visible tab viewport, so inactive-tab previews are page-owned images or intentional imageless cards. Protected pages can be saved as links but cannot be inspected or marked; local `file://` pages may need **Allow access to file URLs**.
- **Deletion is reversible only briefly.** A delete remains undoable for five seconds; afterward it permanently purges local content. Do not export/import while an undo timer or cleanup job is active. A surfaced cleanup error can be retried in the hub; no background failure is treated as a completed deletion.
