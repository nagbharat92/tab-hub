# Round 2 decisions

The unchanged v0.2 brief is in this folder. These decisions record conflicts or details it leaves open; the original requirements remain in `ACCEPTANCE.json`.

1. **Historical preservation rather than a false tag.** `main` was already v0.3.0 (`593111b`), not v0.1.2. Tag the actual v0.1.2 commit (`52d5600`), build that revision in an isolated worktree, and publish its ZIP on the v0.1.2 GitHub release. Archive documents and screenshots from that commit, rather than move the present v0.3.0 files and mislabel them. Rejected: tagging HEAD as v0.1.2, losing historical provenance and packaging the wrong extension.
2. **Advance the installed version, not the version number in the stale brief.** Round 2 starts from v0.3.0 to retain permanent-deletion data safety, region capture repairs, legacy-archive compatibility, and the installed user's data. The next installable manifest will be v0.4.0, even though the brief calls the structural design target v0.2.0. Rejected: downgrade to v0.1.2 and discard v0.3 safeguards, or label v0.3-derived code v0.2.0 and risk an installation/version regression. Do not install this branch in the user's profile.
3. **Use the source of truth that exists.** No v0.1 addendum, Siri images, round-1 recordings, or demo-library archive are present in the repository or previous Tab Hub conversation. Keep the v0.2 brief literal, use its explicit Siri descriptions, the existing v0.1.2 screenshots and real-URL/synthetic fixtures, and mark identical-content before/after comparison unavailable. Rejected: inventing an addendum or claiming to have inspected absent assets.
4. **Licensed development guidance only.** The requested Anthropic frontend-design skill is byte-identical to the Apache-2.0 copy in `anthropics/skills`; vendor it with its license. Vendor the Apache-2.0 Apple skill definition with its license, but do not copy its Apple-owned HIG mirror or its images into this repository or extension. Read only materials, motion, typography, layout, and accessibility foundations as reference. Rejected: redistributing unlicensed mirrored HIG content.
5. **A blank ceiling is not a time or spend limit.** Both ceiling fields contain underscores, not values. Work toward the stop condition, and explicitly disclose any unattained acceptance/evaluator conditions in `SUMMARY.md`; do not silently invent a budget or declare a nonexistent ceiling reached.
6. **Threads are a read-only, idempotent upgrade projection.** `loadThreads()` reads the existing per-card `chrome.storage.local` records and per-card IndexedDB fragments/image keys under the deletion lock, projecting one thread keyed by normalized URL. Each original page card remains a distinct page save; marked fragments remain separate saves with their own IDs, timestamps, images, and source-card/group/order fields. The newest *visible* save is the face; archived saves stay in the thread as `archivedSaves` and never make a previously archived item the visible face. No persisted records, sidecars, media, group ordering, archive metadata, or version-1 backup format are rewritten. A browser restart or interrupted read simply recomputes the same view; backup imports immediately appear in it. The alternative was a multi-store in-place rewrite (requiring a restart-safe transaction spanning Chrome storage and IndexedDB), rejected as an unnecessary loss/race risk for existing v0.3.0 libraries. Existing hub UI remains unchanged until the separate UI pass consumes this API.
7. **URL identity and capture joins.** Remove hashes and the specified case-insensitive sharing/tracking parameters, plus common click identifiers, while retaining all other query parameters in their original order. Malformed pre-existing URLs get a stable, distinct invalid-URL key rather than disappearing; newly captured URLs still require validation. Marks attach to the newest *visible* card in a normalized thread, or create a new visible card when all matches are archived. Group captures keep every durable card and leave close-after-verified-save and deletion locks unchanged. Rejected: matching an exact URL before a newer normalized match, and resurrecting a hidden archived card.
8. **Region anchors and search.** Newly marked regions capture the nearest page element selector, surrounding text and scroll offset; old regions without anchors remain valid and offer no anchor (the detail UI can open those at the top). Version-1 backup validation accepts the optional typed anchor and rejects malformed anchors. Both old card search and new thread search include retained model/user guesses as well as notes, passage text, title, site and URL. Rejected: retroactively inventing coordinates for legacy crops or using an unvalidated backup field.
9. **Changed existing tests (requirements, not weakened assertions).** `tests/e2e/fragments.spec.ts` now asserts the new captured region anchor, required for opening a region at its original spot; `tests/unit/backup.test.ts` now checks optional region-anchor roundtrip/validation without changing its existing cases; `tests/unit/search.test.ts` now checks that a retained model guess is searchable. New `tests/unit/urls.test.ts`, `tests/unit/threads.test.ts` and `tests/e2e/thread-migration.spec.ts` use a synthetic v0.1.2 fixture with UI Inspo, Shop and Individual tabs, Henry/X duplicates, sidecar notes/guesses, images and old-style fragment records, plus v0.3 legacy archives. They prove normalized merge, face/order, IDs and group order, archived isolation, restart, fragment joining, and ZIP export/import with all assets. The unavailable demo-library archive was not claimed or used.
10. **A save and a whole page are different deletion scopes.** Each save gets an independently undoable five-second soft-deletion record; deleting the last visible save must never implicitly delete older archived saves on the same normalized URL. When a page save expires, remove its durable card if it has no remaining marks; otherwise hide only that page save until its last mark is purged. An explicit whole-page deletion refuses to overlap an unresolved save deletion on that same page, so a later undo cannot claim to restore already-purged data. Alternatives: purge every underlying card when the visible page vanishes (destroys unselected legacy archives), or retain empty hidden cards forever (contradicts purging after undo expires).
11. **View-local region scrim.** Render the progressive masked backdrop blur only while the region face is in or near the viewport, and keep the original image bytes unchanged. Alternatives: pre-bake the blur into crops (changes backed-up original images and old fixtures), or leave a live backdrop filter on all visited cards (scroll cost with hundreds of regions).
12. **Chrome's four default shortcut slots.** Use Alt+Shift+1/2/3/4 for group save, tab save, opening the hub, and selected text. The region drag stays available from its popup row and page context menu but does not display a shortcut Chrome cannot register. Read the active bindings with `chrome.commands.getAll()` so user-remapped or disabled shortcuts are displayed accurately. Give only the group row extra weight; an ungrouped tab's save action uses the same weight as the other actions. Reuse an already-open hub tab from both shortcut and popup. Alternatives: advertise a fictitious fifth shortcut, silently steal a Chrome binding, or open a new hub on every popup visit.
13. **Keep broad host access for existing one-action capture.** The extension already has broad host permission from v0.3.0 to inspect all members of a group without shifting the active tab or interrupting save-before-close. Optional host permissions at first use would require interactive grants for arbitrary member domains and silently degrade inactive-tab preview extraction if declined; this is contrary to the original one-action save and could miss important context. Preserve local-only storage and no external inference; revisit narrower permissions with a complete capture redesign rather than silently changing guarantees this round. No new permission was added for anchored region opening.
14. **Synthetic screenshot evidence is not a substitute for the missing demo archive.** Generate reproducible page/passage/region faces, mixed stacks, light/dark and narrow states with local test records and images, keeping user browsing data out of screenshots. Do not claim these captures match the unavailable round-1 recordings or demo-library content. The alternate choice, capturing the user's live profile, would violate the brief's throwaway-profile rule.
15. **Responsive panel without an overlay.** On desktop a selected grid transforms left without changing four-column layout or card sizes, then a right panel arrives. On narrow viewports a third-width panel beside two usable grid columns cannot fit; keep two-column grid unchanged and put its panel directly after the grid in normal document flow, scrolling to it on selection. This preserves full-width cards and avoids a modal or bottom sheet over the grid. Rejected: squeezing the cards to unreadable strips, and the first pass's fixed bottom overlay (obscured grid/toasts and violated the brief's no-overlay panel rule).
16. **Reduced motion and image geometry.** Honor reduced motion by retaining the selected grid's final left position instantly, without animation; fading the panel is sufficient. For pages with a known saved or declared visual, reserve the inset image's final 8:5 geometry until the local blob is ready so loaded previews do not shift cards below. Imageless pages render no slot once the cache confirms there is no image. Region faces have fixed geometry; apply the progressive scrim only in/near the viewport. Alternatives: stopping the reduced-motion grid transform entirely (caused panel/card overlap), allowing asynchronous image heights to rearrange masonry, or applying backdrop blur to hundreds of off-screen region cards.
17. **Quiet narrow header and undo location.** Keep the single header row; make the search field temporarily compact while an active group/type label is present, and use the label itself as the clear control without a redundant visible X. With the panel inline, retain Sonner's bottom-center undo stack and leave room to scroll the panel above it. A trial top-positioned stack covered the wordmark and failed the second evaluator round. Alternatives: truncating ordinary group names, adding a second header row, or keeping toasts over a bottom sheet.
18. **Undo-safe backup boundary.** Refuse export and import while any soft-delete job has an active undo window; otherwise a backup could include hidden content as if deletion never happened, or an import could reintroduce a pending deletion. A pending permanent cleanup remains blocked as before. The file input element is captured before awaiting import so clearing it and resetting busy state always works, including repeated imports. Rejected: silently exporting logically deleted items, or declaring success while the delete timer could still be undone.
19. **The brief's intentional exceptions stay visible.** Do not remove the menu's group/type separator or the popup's two action separators to raise a visual-evaluator score: both are part of the explicit layouts in sections 4 and 8. Hide search and filter on an empty hub as section 9 directs, despite section 2's general header definition. When the brief does not require extra chrome, omit it: no close button on the panel, no count badge, no selection mode, and no extra visible clear icon on the active filter. Alternatives: keep the prior over-labeled and button-heavy UI or indiscriminately remove explicitly requested separators.
20. **Isolate the review build from the installed extension's output path.** Set WXT's output template on this branch to `.output/round-2-chrome-mv3`, and point the throwaway-profile test harness and review instructions there. The default `.output/chrome-mv3` may be the path Chrome already loads for the user's v0.3.0 extension; continuing to rebuild there risks an unintended reload despite never explicitly installing this branch in their browser. Earlier in this pass, before this risk was identified, standard builds did write to that default output path; rebuild v0.3.0 at that path without loading or modifying the Chrome profile. Rejected: claiming that simply avoiding a Playwright test on the personal profile isolates the build directory.
21. **No initial region-selection instruction chip.** The popup names the action and the cursor changes to a crosshair; remove the region overlay's extra floating drag tutorial to satisfy the brief's no-instruction-copy rule. Keep the Cancel control for users who cannot press Esc, and reveal a status chip only for too-small selections or failed saves, when feedback is necessary. Rejected: silent errors or forcing keyboard Escape as the only exit path.
22. **Existing dark ink for small metadata.** On lifted grey dark cards the inherited muted text (#919191) against the card (#474747) has approximately 2.95:1 contrast at 12px and failed evaluator review. Use the already-defined primary-ink token for card metadata in dark mode (approximately 6.91:1 against the card), preserving every colour value and distinguishing meta by type size and placement. Rejected: inventing a new colour this structural round or leaving unreadable small text.
23. **Calendar dates, not 24-hour chunks.** The relative Today/Yesterday/weekday labels use the user's local calendar day projected into UTC for subtraction, so a 23-hour daylight-saving day still counts as Yesterday. Rejected: elapsed-milliseconds / 24h, which can render yesterday as Today on the spring transition. A focused existing-runner unit test covers the transition.
24. **Content-set image heights.** Region faces and page inset images take their height from the loaded image's natural aspect (clamped to 0.7–1.5 for regions, 1.1–2.2 for page insets so one extreme crop cannot dominate a column), with a neutral placeholder geometry while the local blob loads. Rejected: a fixed aspect ratio (contradicts section 5's "Height: set by content") and unclamped ratios (a 1×1000 crop would create a column-long card). Images load in a 240px pre-viewport margin, so the one-time size settle happens mostly off screen.
25. **Region selector uses system colours.** The drag overlay runs inside arbitrary pages, where the extension's CSS variables do not exist. Use CSS system colours (`Canvas`, `CanvasText`, `Highlight`, `GrayText`) instead of duplicating raw token values, so no component carries a raw colour and the Tab Hub accent stays in its three allowed places. Rejected: hard-coded copies of the light theme values (a round-3 reskin would miss them).
26. **Save fade and hover depth.** A deleted save fades for 180 ms before its soft delete is written, matching "that save fades out". Hover deepens the card shadow by layering the existing shadow token twice rather than adding a new colour token. Rejected: an instant removal, or a new unlisted shadow token.
27. **Legacy archive entry in More.** When only pre-0.3 archived records exist, section 9 hides search and filter, leaving no route to them; More adds *Previously archived* in that case only. Rejected: showing an empty grid with search/filter for a library whose visible content is empty, or stranding a user's legacy records.
28. **Changed tests after the first report.** `tests/e2e/delete*.spec.ts`, `backup`, `capture`, `extension`, `fragments`, `how-it-works`, `hub`, `legacy-archive`, `notes-ai`, `real-urls`, `region-regression`, `scale` and `thread-migration` were retargeted from removed UI (confirmation dialogs, Details, rail counts, top-level Export/Import, guide button) to the equivalent current behaviour; every data-safety assertion (verified close, media purge, orphan cleanup, restart recovery, conflict-safe import, lock ordering) was kept and now also exercises the five-second expiry. Fixed sleeps were replaced with polling. New: undo-window backup refusal, archived-history preservation, meta-line dates/handles, page-opens-at-top. `design.spec.ts` was rewritten to capture the round-2 matrix and optional recordings.
